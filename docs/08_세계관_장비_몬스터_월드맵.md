## 2. 장비/인벤토리 시스템

### 핵심 원칙

```
"장비는 일관성이 있다. 입으면 보이고, 잃으면 없다."
```

- 캐릭터가 획득한 아이템은 DB에 기록
- 이후 모든 이미지/영상에서 해당 아이템이 프롬프트에 반영
- 아이템 파손/분실 시 프롬프트에서 제거 + 상태 반영
- NPC도 동일하게 인벤토리 관리

### 아이템 등급

| 등급 | 색상 | 프롬프트 효과 | 획득 방법 |
|------|------|-------------|----------|
| **common** | 흰색 | 특별 묘사 없음 | 상점, 드롭 |
| **uncommon** | 초록 | 세부 묘사 추가 | 퀘스트, 제작 |
| **rare** | 파랑 | 은은한 빛 + 세부 묘사 | 보스 드롭, 특수 퀘스트 |
| **epic** | 보라 | 마법 이펙트 + 아우라 | 던전 클리어, 중간보스 |
| **legendary** | 주황 | 강한 발광 + 환경 영향 | 재해급 처치, 시즌 보상 |
| **mythic** | 빨강 | 세계 반응 (주변이 변함) | 마왕 관련, 시즌 최종 |

### 아이템이 프롬프트에 반영되는 방식

```typescript
// prompt-builder가 캐릭터 프롬프트 생성 시
function buildCharacterPrompt(char: Character): string {
  let prompt = char.base_appearance; // 기본 외모

  // 장착 아이템 순회
  for (const item of char.equipped_items) {
    if (item.status === 'equipped') {
      prompt += `, ${item.visual.prompt_tag}`;
    } else if (item.status === 'damaged') {
      prompt += `, ${item.visual.prompt_tag_damaged}`;
    }
    // 등급별 이펙트
    if (item.rarity === 'rare') prompt += ', faint magical glow';
    if (item.rarity === 'epic') prompt += ', visible magical aura';
    if (item.rarity === 'legendary') prompt += ', strong radiant glow affecting surroundings';
  }

  return prompt;
}
```

매 에피소드마다 이 상태가 프롬프트에 자동 반영.

### 아이템 비주얼 일관성 — 3 Tier 전략

아이템 등급에 따라 일관성 보장 수준이 다르다.

#### Tier 1 — 프롬프트 고정 (common ~ uncommon)

DB의 `visual.prompt_tag`를 매번 동일하게 주입. 별도 이미지 생성 없음.
Flux가 매번 약간 다르게 해석할 수 있지만, "비슷한 검" 수준이면 OK.
대부분의 소모품, 일반 장비가 여기.

```
비용: 0
정확도: ~70%
관리: prompt_tag만 DB에 저장
```

#### Tier 2 — 레퍼런스 이미지 (rare ~ epic)

캐릭터 생성과 동일한 방식:

```
1. 아이템 단독 이미지 Flux로 10~20장 생성
   프롬프트: "detailed item photo on neutral background, {item.prompt_tag}, 
   studio lighting, product photography, isolated object, high detail"
   
2. 웹 UI에서 앵커 1장 선정 (캐릭터 선택과 같은 UI 재활용)

3. 앵커에서 다각도 파생 (IP-Adapter)
   - 정면 (front view)
   - 45도 (three quarter)
   - 장착 상태 (held by hand, worn on body)
   - 손상 상태 (cracked, damaged)
   - 강화 상태 (glowing, enchanted)

4. Oracle item_ref_images 테이블에 저장
   - image_path, CLIP 임베딩, state (normal/damaged/enhanced)

5. 씬 생성 시 IP-Adapter에 두 개 참조 동시 주입
   - ref_1: 캐릭터 앵커 (weight 0.6)
   - ref_2: 아이템 앵커 (weight 0.3)
   → 캐릭터와 아이템 둘 다 일관성 유지
   
6. CLIP 유사도 검증
   - 생성된 씬에서 아이템 영역 vs 앵커 유사도 체크
   - 0.8 미만이면 재생성
```

```
비용: 아이템당 Flux 10~20장 + IP-Adapter 파생 5~8장
정확도: ~90%
관리: item_ref_images 테이블 + CLIP 임베딩
```

#### Tier 3 — LoRA 학습 (legendary ~ mythic)

시즌 내내 등장하는 핵심 아이템은 전용 LoRA로 학습.

```
대상: 소율이 지팡이, 세리온의 검, 마왕의 검, 전설 아이템 등
학습: Kohya ss, rank 16~32, 500~1000 steps
트리거 워드: "soyul_staff", "serion_sword" 등
15~20장 레퍼런스 이미지 (Tier 2에서 생성한 것 활용)
```

```
비용: LoRA 학습 30~60분 (3090), 아이템당 1회
정확도: ~97%
관리: lora_training_log 테이블 + models/loras/
```

#### Tier 할당 기준

| 아이템 등급 | Tier | 이유 |
|-----------|------|------|
| common | 1 | 자주 안 나옴, 비용 대비 효과 낮음 |
| uncommon | 1 | 몇 번 나오지만 디테일 불필요 |
| rare | 2 | 반복 등장, 시청자가 인지하는 아이템 |
| epic | 2 | 스토리 중요 아이템, 일관성 필수 |
| legendary | 3 | 시즌 핵심 아이템, 완벽한 일관성 필요 |
| mythic | 3 | 마왕 관련, 시각적 임팩트 최대 |

#### 상태별 프롬프트 자동 전환

아이템 상태가 바뀌면 프롬프트가 자동으로 전환:

```typescript
function getItemPrompt(item: Item): string {
  switch (item.status) {
    case 'equipped':
      // Tier 2+면 ref 이미지도 전환
      return item.visual.prompt_tag;  
    case 'damaged':
      return item.visual.prompt_tag_damaged;
    case 'broken':
      return item.visual.prompt_tag_broken;
    case 'enhanced':
      // +레벨에 따라 발광 추가
      const glow = getEnhancementGlow(item.enhancement_level);
      return `${item.visual.prompt_tag}, ${glow}`;
    default:
      return item.visual.prompt_tag;
  }
}

function getEnhancementGlow(level: number): string {
  if (level <= 0) return '';
  if (level <= 2) return 'faint magical shimmer';
  if (level <= 4) return 'visible magical glow, light particles';
  if (level <= 6) return 'intense radiant aura, pulsing light';
  return 'blinding divine light, reality warping around weapon';
}
```

#### Oracle 추가 테이블

```sql
CREATE TABLE item_ref_images (
    ref_id          NUMBER GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
    item_id         VARCHAR2(50) REFERENCES items(item_id),
    image_path      VARCHAR2(500) NOT NULL,
    image_embedding VECTOR(512, FLOAT32),     -- CLIP 임베딩
    state           VARCHAR2(20) DEFAULT 'normal',  -- normal/damaged/enhanced/broken
    angle           VARCHAR2(20),              -- front/side/equipped/closeup
    is_anchor       NUMBER(1) DEFAULT 0,
    quality_score   NUMBER(3,2),
    created_at      TIMESTAMP DEFAULT SYSTIMESTAMP
);

CREATE INDEX idx_item_ref_vector ON item_ref_images (image_embedding)
    INDEXTYPE IS CTXSYS.CONTEXT
    PARAMETERS ('type HNSW distance COSINE accuracy 95');
```

## 4. 몬스터 계층 시스템

### 위험 등급

```
일반 → 정예 → 중간보스 → 보스 → 재해급 → 마왕
```

| 등급 | 위협 수준 | 출현 빈도 | 처치 보상 | 필요 파티 |
|------|----------|----------|----------|----------|
| **일반** (Normal) | 낮음 | 매우 흔함 | common 아이템 | 솔로 가능 |
| **정예** (Elite) | 중간 | 흔함 | uncommon 아이템 | 2인 이상 |
| **중간보스** (Mini Boss) | 높음 | 드묾 | rare 아이템 | 풀파티 |
| **보스** (Boss) | 매우 높음 | 던전당 1마리 | epic 아이템 | 풀파티 + 전략 |
| **재해급** (Calamity) | 극도 | 시즌당 1~2 | legendary 아이템 | 연합군 |
| **마왕** (Demon King) | 최극 | 시즌 피날레 | mythic 아이템 | 세계 전체 |

```typescript
function buildScenePrompt(scene: Scene): string {
  const location = await db.getLocation(scene.location_id);
  const charPrompts = await buildCharacterPrompts(scene.characters);
  
  // Layer 1: 글로벌 스타일
  let prompt = globalStyle;
  
  // Layer 2: 장소 기본 + 시간대/날씨 변형
  prompt += `, ${location.prompt_base}`;
  prompt += `, ${location.prompt_variants.time_of_day[scene.time_of_day]}`;
  if (scene.weather) {
    prompt += `, ${location.prompt_variants.weather[scene.weather]}`;
  }
  
  // Layer 3: 캐릭터 (장비 포함)
  prompt += `, ${charPrompts}`;
  
  // Layer 4: Claude가 생성한 씬 고유 디테일
  prompt += `, ${scene.prompt_en}`;
  
  return prompt;
}

// IP-Adapter 참조 자동 선택
async function selectReferences(scene: Scene): Promise<RefSet> {

    scene.location_id, scene.time_of_day, scene.weather
  );
  
  return {
    character: { image: charRef, weight: 0.6 },
    location: { image: locationRef, weight: 0.25 },
    // 아이템은 Phase 2
  };
}
```

## 6. 전투 시스템 (대본 반영용)

### 전투 결과 계산 (Python)

실시간 전투가 아닌 **결과 시뮬레이션**. Claude가 대본 쓸 때 참고.

```python
def simulate_battle(party: list[Character], enemies: list[Monster]) -> BattleResult:
    """
    파티 vs 몬스터 전투 결과를 시뮬레이션.
    결과는 확정이 아니라 "가능한 시나리오"를 Claude에게 제공.
    
    반환:
    - win_probability: 승률 (0~1)
    - suggested_outcome: "victory" | "narrow_victory" | "retreat" | "defeat"
    - key_moments: ["세리온이 고블린 왕을 몰아붙임", "리나엘의 마법이 오발"]
    - casualties: 예상 피해 (HP 감소, 장비 파손 등)
    - drama_score: 드라마틱한 정도 (0~1)
    """
```

Claude 대본 생성 시 이 결과를 컨텍스트로 받고, 실제 전투 묘사는 Claude가 창작.
"승률 60%, 핵심 순간: 소율의 좋아요 버프가 결정타" 같은 가이드라인.

### 전투에서 장비 변화

```
전투 결과에 따라:
- 무기 내구도 감소 (5~20%)
- 심한 전투 시 장비 파손 가능 (10% 확률)
- 보스 처치 시 드롭 아이템 획득 → 인벤토리 추가
- 패배 시 아이템 분실 가능 (5% 확률)
→ 모든 변화가 Oracle에 기록
→ 다음 씬 프롬프트에 자동 반영
```

```json
    {"name": "마왕군 정찰대 목격됨", "region": "중앙 평원", "severity": "low"}
  ]
}
```

### 장비 변경 시 자동 처리

```
1. 대본에서 장비 변경 이벤트 발생
   → Claude JSON에 equipment_changes 포함

2. Node.js가 equipment_changes 파싱
   → character_inventory 테이블 UPDATE
   → item_history INSERT
   → 장비 상태 프롬프트 태그 갱신

3. 다음 씬부터 해당 캐릭터 프롬프트에 자동 반영
```
