# 05. 영상 생성 파이프라인

> 대본 확정 → Flux 키프레임 → Wan 2.2 영상화 → TTS → 업스케일 → 품질 검증
> 2026-03-27

---

## 전체 흐름

```
DB에서 확정 대본 로드 (scenes 테이블)
    ↓
Pass 1 — Flux 이미지 생성 (전체 씬 키프레임)
    ↓ 품질 검증 → 불량 재생성
Flux 모델 언로드
    ↓
Pass 2 — Wan 2.2 I2V 영상 생성 (전체 씬)
    ↓ 품질 검증
병렬: TTS 음성 + BGM/효과음 선택
    ↓
Real-ESRGAN 업스케일 (480p → 1080p)
    ↓
Oracle DB 저장 (경로, 메타, 임베딩)
    ↓
후처리 파이프라인으로 전달
```

**핵심 제약**: Flux와 Wan 2.2는 동시 로드 불가 (3090 24GB).
반드시 **2패스 순차 처리**.

## 1. Pass 1 — Flux 키프레임 이미지 생성

### 입력

```sql
-- 확정된 에피소드의 전체 씬 로드
SELECT s.scene_order, s.prompt_en, s.camera_type, s.time_of_day,
       s.characters_present, s.emotion, s.duration_sec
FROM scenes s
WHERE s.ep_id = :ep_id AND s.status = 'approved'
ORDER BY s.scene_order
```

### 프롬프트 조합

씬마다 3계층 프롬프트 자동 조합:

```
Layer 1 (글로벌, 고정):
  realistic smartphone footage, amateur camera work,
  slightly imperfect framing, natural lighting,
  photorealistic, raw photo, NOT anime

Layer 2 (씬 타입, DB에서 로드):
  camera_type → selfie/exploration/action/dialogue/night/mukbang 프리셋

Layer 3 (씬 고유, Claude가 생성한 prompt_en)

시간대 프롬프트 (time_of_day → 자동 주입):
  morning/afternoon/evening/night/rain 프리셋

캐릭터 태그 (characters_present → DB에서 외모 태그 로드)
```

### 캐릭터 참조 이미지 자동 선택 (Vector Search)

```sql
-- 이 씬에 가장 적합한 참조 이미지
SELECT ri.image_path, ri.pose_tag
FROM char_ref_images ri
WHERE ri.char_id = :char_id AND ri.approved = 1
ORDER BY VECTOR_DISTANCE(ri.image_embedding, :scene_embedding, COSINE)
FETCH FIRST 1 ROWS ONLY
```

IP-Adapter에 이 참조 이미지를 넘겨서 캐릭터 일관성 유지.

### ComfyUI WebSocket API 호출

```typescript
// Node.js → ComfyUI
const workflow = {
  "UnetLoaderGGUF": { unet_name: "flux-2-klein-9b-Q5_K_M.gguf" },
  "CLIPLoader": { clip_name: "qwen_3_8b_fp8mixed.safetensors", type: "flux" },
  "VAELoader": { vae_name: "flux2-vae.safetensors" },
  "CLIPTextEncode": { text: combinedPrompt },
  "EmptySD3LatentImage": { width: 1024, height: 1024 },
  "KSampler": { steps: 20, cfg: 3.5, sampler: "euler", scheduler: "simple" },
  "IPAdapterApply": { image: referenceImagePath, weight: 0.6 },
  // LoRA가 있으면 추가
};
```

### 배치 처리 전략

에피소드 전체 씬(7~10씬)의 키프레임을 한 번에 큐잉:

```
씬1 → [이미지 생성] → 품질 체크 → OK → 다음
씬2 → [이미지 생성] → 품질 체크 → FAIL → 재생성 → OK → 다음
...
전체 씬 완료 → Flux 모델 언로드 → Pass 2 시작
```

Klein 9B 기준: 씬당 1~2장 × 7씬 = 14장 × 3~5초 = **약 1분**

### 자동 품질 검증

| 검증 항목 | 방법 | 기준 |
|----------|------|------|
| 얼굴 감지 | InsightFace | confidence > 0.7 |
| 캐릭터 일치 | CLIP 코사인 유사도 (앵커 vs 생성) | > 0.85 |
| 프롬프트 준수 | CLIP 텍스트-이미지 유사도 | > 0.25 |
| 선명도 | 라플라시안 분산 | > 100 |
| 손가락 | InsightFace + 수동 (선택) | - |

불량 시 시드 변경 후 최대 3회 재생성. 3회 실패 시 웹 UI 알림 → 사람이 프롬프트 수정.

## 2. Pass 2 — Wan 2.2 I2V 영상 생성

### 모델 전환

```
Flux 모델 전체 언로드 → VRAM 해제 (약 3초)
→ Wan 2.2 I2V + Lightx2v LoRA 로드 (~18GB)
```

Node.js에서 ComfyUI API로 모델 언로드/로드 제어.

### 입력

- Pass 1에서 생성된 키프레임 이미지 (1024×1024)
- 씬별 모션 프롬프트 (Claude가 생성한 motion_prompt)
- 기본 설정: 480×320, 81프레임(5초) 또는 161프레임(10초), 16FPS

### 모션 프롬프트 템플릿 (6종)

| 씬 타입 | 모션 프롬프트 |
|---------|-------------|
| 대화 | person talking, natural gestures, slight head tilt, mouth moving |
| 이동 | walking forward, camera bobbing, scenery moving, hair flowing |
| 전투 | quick movements, dodging, dust rising, chaotic camera shake |
| 리액션 | surprised expression, stepping back, eyes widening, comedic |
| 셀카 | girl talking to camera, slight head movements, wind blowing hair |
| 풍경 | slow camera pan, clouds moving, smoke rising, ambient movement |

Claude의 motion_prompt가 이 템플릿을 기반으로 커스터마이징한 것.

### Wan 2.2 설정

```json
{
  "model": "Wan2.2-I2V-A14B-HighNoise-Q4_K_S.gguf",
  "lora": "lightx2v_wan2.2_lora_4step.safetensors",
  "width": 480,
  "height": 320,
  "frames": 81,
  "fps": 16,
  "steps": 4,
  "cfg": 1.0,
  "denoise": 0.8
}
```

### 배치 처리

```
씬1 키프레임 → [Wan I2V] → 5초 영상 → 품질 체크 → OK
씬2 키프레임 → [Wan I2V] → 10초 영상 → 품질 체크 → OK
...
```

씬당 Wan 2.2 생성 시간: 약 15~20분 (3090, 4step)
7씬 기준: **약 2~2.5시간**

### 영상 품질 검증

| 검증 항목 | 방법 | 기준 |
|----------|------|------|
| 프레임 일관성 | 첫/마지막 프레임 CLIP 유사도 | > 0.8 |
| 모션 자연스러움 | 옵티컬 플로우 분산 | 범위 내 |
| 얼굴 유지 | 중간 프레임 얼굴 감지 | > 0.6 |
| 아티팩트 | 프레임간 급격한 색상 변화 감지 | - |

불량 시 시드 변경 또는 denoise 조정 후 재생성.

## 3. 병렬: TTS + BGM/효과음

Pass 2와 동시에 진행 가능 (CPU/Python으로 별도 처리).

### TTS (Qwen3-TTS)

Node.js → `POST http://localhost:8000/api/tts/generate`

```json
{
  "scenes": [
    {
      "scene_order": 1,
      "dialogues": [
        {
          "char": "소율",
          "line": "여러분 안녕하세요~",
          "speaker": "sohee",
          "instruct": "밝고 에너지 넘치는 10대 소녀, 유튜버 말투"
        },
        {
          "char": "태양",
          "line": "서라, 어디서 왔느냐?",
          "speaker": "aiden",
          "instruct": "깊고 진지한 남성, 중세 기사 말투"
        }
      ]
    }
  ]
}
```

캐릭터별 speaker + instruct는 Oracle `characters.voice_config`에서 로드.

### BGM/효과음 자동 선택 (Vector Search)

```sql
-- 씬 감정에 맞는 BGM
SELECT bgm_path, mood_tags, duration
FROM external_references
WHERE type = 'bgm' AND license = 'CC0'
ORDER BY VECTOR_DISTANCE(mood_embedding, :scene_emotion_embedding, COSINE)
FETCH FIRST 3 ROWS ONLY
```

```sql
-- 효과음 (씬의 sfx 목록 기반)
SELECT sfx_path, description
FROM external_references
WHERE type = 'sfx' AND license = 'CC0'
  AND description_embedding IS NOT NULL
ORDER BY VECTOR_DISTANCE(description_embedding, :sfx_query_embedding, COSINE)
FETCH FIRST 1 ROWS ONLY
```

## 5. Oracle 저장

각 단계 결과를 DB에 기록:

```sql
-- 씬 상태 업데이트
UPDATE scenes SET
  status = 'video_ready',
  keyframe_path = :keyframe_path,
  video_path = :video_path,
  upscaled_path = :upscaled_path,
  tts_path = :tts_path,
  bgm_path = :bgm_path,
  quality_score = :score,
  generation_time_sec = :elapsed
WHERE scene_id = :scene_id;

-- 프레임 임베딩 저장 (품질 추적용)
INSERT INTO frame_references (scene_id, frame_idx, image_embedding, quality_score)
VALUES (:scene_id, :idx, :embedding, :score);

-- 프롬프트 레퍼런스 저장 (자동 진화용)
INSERT INTO prompt_references (prompt_text, prompt_embedding, quality_score, tags)
VALUES (:prompt, :embedding, :score, :tags);
```

## 6. 전체 타임라인 (1 에피소드, 7씬 기준)

| 단계 | 소요 시간 | 비고 |
|------|----------|------|
| Flux 키프레임 (7씬 × 2장) | ~1분 | Klein 9B, 병렬 불가 |
| 품질 검증 + 재생성 | ~5분 | 자동, 불량 시 추가 |
| 모델 전환 (Flux→Wan) | ~10초 | 자동 |
| Wan 2.2 영상 (7씬) | ~2.5시간 | 가장 오래 걸림 |
| TTS (병렬) | ~5분 | Python, CPU |
| BGM/SFX 선택 (병렬) | ~1분 | Vector Search |
| 업스케일 (7씬) | ~45분 | ESRGAN |
| 품질 검증 + DB 저장 | ~5분 | 자동 |
| **합계** | **~3.5시간** | 대부분 GPU 대기 |

## 7. API 엔드포인트

```
POST   /api/episodes/:epId/generate-video
       → 전체 영상 생성 시작 (BullMQ 큐 등록)

GET    /api/episodes/:epId/generation-status
       → 전체 진행 상황 (씬별 단계, %)

GET    /api/episodes/:epId/scenes/:sceneId/preview
       → 개별 씬 미리보기 (영상/이미지)

POST   /api/episodes/:epId/scenes/:sceneId/regenerate
       → 특정 씬 재생성 (키프레임 or 영상)

WS     /ws/generation/:epId
       → 실시간 진행 스트리밍
```
